# ADR 0008: The public dashboard stays public, and its process holds nothing worth stealing

**Status:** accepted (2026-11-21, after the dashboard went live at
`https://bot.alexeymagay.com`). Builds on ADR 0006.

## Context

The public API returns only shareable numbers (ADR 0006, enforced by
tests): weights, prices, signals, index-100 equity. A login in front of
it would protect nothing secret today, and the dashboard is meant as a
public showcase.

The real exposure was *behind* the page. The public `api` container was
built from the same Compose anchor as the engine, so it got:

- the repo-root `.env` via `env_file`: Binance testnet keys once sandbox
  starts, Kraken keys if Phase 7 is ever unlocked, the ntfy token;
- the owner Postgres role, which `postgres:16` makes a **superuser**
  (and so able to run shell commands in the database container via
  `COPY ... TO PROGRAM`);
- read-write `market_data/` and `reports/` mounts.

So one remote-code bug anywhere in FastAPI, Starlette, uvicorn, pandas
or our handlers would have been a path to broker keys and to writing the
`kill_switch_state` and `sleeve_state` rows the engine trusts. A login
only decides who can *see* the page; it doesn't change what a
compromised process can reach.

## Options

1. **Login in front** (Cloudflare Access, basic auth, WireGuard-only).
   Shrinks who can send requests; the process still holds every secret.
   And it defeats the point of a public dashboard.
2. **Least privilege for the public process, plus edge hardening**
   *(chosen)*.
3. Both. Still available if the dashboard ever needs to show something
   private; nothing here precludes it.

## Decision

The public process gets nothing beyond what it needs to serve the page:

- **No secrets.** The `api` service is written out in full, not from the
  `*engine` anchor: no `env_file`; only a DSN, the trusted-proxy CIDRs and
  log format.
- **A SELECT-only Postgres role**, `kestrel_public` (`api/db_role.py`):
  `SELECT` on exactly `api.queries.PUBLIC_TABLES` (not `orders`,
  `instruments`, `trial_ledger`, `holdout_access`), with
  `default_transaction_read_only`, a 5 s `statement_timeout` and a 20-
  connection limit. `kestrel admin ensure-public-role` resets the grants;
  the prod `migrate` service runs it after every migration, so grants
  follow the schema. Its password lives in `deploy/.env` (generated by
  `deploy.sh`), separate from the owner's.
- **A locked-down container**: read-only root filesystem (16 MB noexec
  `/tmp`), no data volumes, `cap_drop: ALL`, `no-new-privileges`, a PID
  limit. The engine containers also drop all capabilities.
- **App**: Swagger/OpenAPI off in production; unknown `/api/*` paths are
  JSON 404s instead of the dashboard shell; at most 50 concurrent
  `/api/stream` connections.
- **Nginx** (`deploy/nginx/kestrel.conf`, this server name only): GET/HEAD
  only, 1 KB body limit, short header/body timeouts, per-IP connection
  and request limits on pages too (not just `/api/`), `server_tokens
  off`, HSTS, a strict CSP (scripts from this origin only), framing denied,
  Permissions-Policy, COOP. The docs paths are also blocked here.

## Consequences

- `tests/unit/live/test_public_role.py` runs every public endpoint as
  `kestrel_public` and checks it can't read the excluded tables or write
  anything. **A query on a new table must add its model to
  `PUBLIC_TABLES`**, or that test fails.
- Remaining public information: the strategy's full internals (Decisions
  page) and bot health. Fine for paper trading. If live trading at size
  makes front-running a concern, revisit with option 3 or a delayed feed.
- CSP keeps `'unsafe-inline'` for *styles* (React and the chart library
  set inline styles; there is no browser on the VPS to prove a stricter
  policy safe). Inline *scripts* are blocked. Google Fonts remains a
  third party; self-hosting the font would drop it from the CSP.
- Not done: Cloudflare proxying/WAF (the DNS record stays grey-cloud like
  the box's other sites), fail2ban (another host service). Neither is
  needed for a read-only page with these limits.
